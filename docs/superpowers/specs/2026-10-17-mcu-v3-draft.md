# BonettoR32V MCU (contract v3): DRAFT for the user's review

Status: **draft**. Nothing here is built or decided until the user approves it. Decisions marked
**[Decide]** are the user's. Each one lists the lead's recommendation first. Area figures are the
lead's **projections** (sky130_fd_sc_hd with the H004 synthesis config, about 20 µm² per
flip-flop). None of them is measured yet.

## 1. Intent

Turn the area-minimal RV32E core into a small but genuinely useful microcontroller that fits ONE
Tiny Tapeout 1x1 tile. "Useful" is measured against an Arduino Uno: blink and dim LEDs, read
buttons, talk over serial, run a timer, drive a servo or buzzer, and act as an **IR remote**
(transmit and receive). It should boot and run standalone from the QSPI Pmod's flash, and accept
new programs over USB through the demo board's RP2350, like an Arduino.

- **Goal:** Arduino-class *peripherals and usability* in one 1x1 tile.
- **Non-goal:** Arduino-class *speed*. The core trades speed for area (section 9).
- **Anti-goal:** a peripheral set so big the core has to grow back on-die registers, or the
  design misses 1x1.

## 2. Budget

| Item | Area (µm²) |
|---|---|
| 1x1 cap, stock TT flow, timing-repair buffers included (measured, Task 8) | ~13,900 |
| Core today: H002 V2 (registers + pc in RAM) / H005 in progress | 5,186 / ~4,900 (measured on branches) |
| Room for peripherals and the bus, keeping ~1,000 margin for repair buffers | **~8,000** |

## 3. Core changes (small)

- **Peripheral bus.** IO space stays at `addr[31] = 1`. Registers decode from `addr[6:2]` (32
  word slots), and everything else aliases. Byte and word accesses both work: a register's bits
  sit in the low byte(s).
- **Interrupts** (section 6). Exceptions trap to `mtvec` (decided).
- **Memory:** 24-bit addresses, two chip selects (flash, PSRAM A) and the reset sequence (section 4).
- **WFI** stops all SPI traffic until an interrupt is pending. That's the low-power idle.
- **Unchanged:** RV32E, spec-minimum decode, the core region for registers, the pc and the IR.

## 4. Memory board and pins (decided: TT QSPI Pmod)

- **Board:** the TT ETR demoboard. Its RP2350B is wired to all ASIC I/O, the clock and reset.
- **Memory:** TT's official QSPI Pmod on the bidirectional header. Verified 2026-10-17 against
  TT's pinouts page and flashing guide.
  - **Flash:** W25Q128JV, 16 MB, ID EF 70 18. First-party Pmods ship with the QE bit set, so
    WP/HOLD are inactive.
  - **PSRAM:** two 8 MB chips, APS6404L class. The part is still to confirm from the Pmod
    schematic; the timing below is from the APS6404L-3SQR datasheet.

| Pin | Function | Direction |
|---|---|---|
| uio[0] | flash CS_n | out |
| uio[1] | MOSI (SD0) | out |
| uio[2] | MISO (SD1) | in (out only during the reset sequence) |
| uio[3] | SCK | out |
| uio[4], uio[5] | SD2, SD3 (flash WP, HOLD) | out, high (driven during the reset sequence) |
| uio[6] | RAM A CS_n | out |
| uio[7] | RAM B CS_n | out, held high (RAM B unused: 8 MB is plenty) |

User pins: 8 `ui` plus 8 `uo`. There is no bidirectional GPIO and no I2C (user, 2026-10-17).
ALTFN picks one function per pin:

| Pin | Function |
|---|---|
| uo[0] | GPIO / UART TX (TT convention: the RP2350 bridges it to USB serial) |
| uo[1] | GPIO / PWM0, IR carrier |
| uo[2] | GPIO / PWM1 |
| uo[3] | GPIO / PWM2 |
| uo[4] | GPIO / SPI-master CS_n |
| uo[5] | GPIO / SPI-master SCK / delta-sigma feedback |
| uo[6] | GPIO / SPI-master MOSI |
| uo[7] | GPIO / timer compare out: tone, servo (TT Audio Pmod mono pin) |
| ui[0] | GPIO in / timer capture (IR receiver) |
| ui[1] | GPIO in / UART RX (TT convention: from the RP2350's USB serial) |
| ui[2] | GPIO in / delta-sigma comparator |
| ui[3] | GPIO in / SPI-master MISO |
| ui[7:4] | GPIO in |

Every `ui` pin can raise an edge interrupt. The demo board's 7-segment display shows `uo`, and
its DIP switches share `ui`.

**Memory map (lead proposal):**
- `0x0000_0000-0x00FF_FFFF` **flash**, read-only while the program runs. The reset pc is
  `0x0000_0000`. Fetches and loads.
  - Stores to flash change nothing: the core never sends write-enable, so the flash ignores a
    program command. The core may skip the transaction or send it.
- `0x0100_0000-0x017F_FFFF` **PSRAM A.** Fetches, loads and stores.
- **Core region** (x1..x15, pc, any core state): the top 128 bytes of PSRAM A,
  `0x017F_FF80-0x017F_FFFF`, inside one 1 KB page.
- `addr[24]` picks the chip select, and `addr[31] = 1` is IO. Other bits alias (spec minimum).

**Protocol:** single SPI, mode 0, 24-bit addresses. READ is `0x03` and WRITE is `0x02` (PSRAM
only). Quad mode is a later speed hypothesis.

**Hard limits from the parts** (datasheet values):
- **PSRAM CS_n low ≤ 8 µs per transaction** (tCEM, standard grade). This sets a **minimum
  clock**: a 4-byte transaction is 64 SCK = 128 clocks, which needs ≥ 16 MHz. No slow-clock
  stepping while PSRAM holds live data. The flash has no such limit.
- **SCK:** PSRAM `0x03` read ≤ 33 MHz (tCLK ≥ 30.3 ns); flash `0x03` ≤ 50 MHz. With SCK ≤ clk/2,
  40 MHz gives 20 MHz.
- **CS_n high** ≥ 18 ns between transactions (tCPH): one clock at 40 MHz.
- **Data out** tACLK ≤ 5.5 ns after the SCK falling edge (PSRAM).
  - The round trip through TT's pads and mux is **unmeasured**. At 40 MHz the MISO sample may
    need one extra clock; TinyQV needed extra read latency at 50 MHz.
- **Pages:** linear bursts cross 1 KB pages while tCEM is met. Our aligned transactions of ≤ 4
  bytes and the core region never cross one.

**Consequence for the 1,024-cycle cap:**
- The 24-bit header adds 8 SCK (16 clocks) to every transaction compared with v2.
- H005 (16-bit addresses) has a 68-cycle margin. Its worst instruction (SW, 956 cycles) makes
  several region transactions, so it would break the cap.
- Contract v3 must re-derive the cap from measurements (and from interrupt latency), or v3
  designs make fewer region transactions. **[Lead to propose with numbers.]**

**Reset sequence (user, 2026-10-17: the core does it, so the chip boots on any board):**
- **EEI assumption:** rst_n is released ≥ 150 µs after VDD is stable (PSRAM tPU). The core
  holds every CS_n high while rst_n is low.
- Before the first fetch, the core brings both chips to SPI standby from any state another
  design may have left:
  1. **Flash:** the continuous-read mode-bit reset, `0xFF` clocked with SD0-SD3 all high. The
     core drives uio[2] for this.
  2. **PSRAM A:** Exit Quad Mode `0xF5` in QPI form (nibbles F, 5 on SD3..SD0), then Reset Enable
     `0x66` and Reset `0x99` in SPI form. The datasheet requires a reset after power-up. Wait
     tRST ≥ 50 ns before the next command.
- **Projected:** 150-300 µm² (a small sequencer sharing the SPI shifter, plus the uio[2] output
  enable) and about 60 clocks.
- **Gates:**
  - The cosim memory models start in random states: SPI, QPI, continuous read.
  - The SPI monitor checks the sequence.
  - The first-retirement cap includes it.

## 5. Peripherals

All registers are 32-bit slots at `0x8000_0000 + 4*n`. The table gives the lead's proposed map.

| Slot | Name | Bits | Function |
|---|---|---|---|
| 0 | GPIO_OUT | 8 | `uo_out` (as today) |
| 1 | GPIO_IN | 8 | `ui_in` (as today) |
| 3 | ALTFN | 8 | per-pin alternate-function enables (UART TX, PWM0-2, compare out, SPI master, delta-sigma) |
| 4 | TIMER_CNT | 16 | free-running counter; a write sets it |
| 5 | TIMER_CTRL | 8 | prescaler (2^0..2^15, 4 bits), compare-out mode (toggle / PWM / off), capture edge (rise / fall / both), enables |
| 6 | TIMER_CMP | 16 | compare value. A match sets IRQ_CMP; optionally auto-reload sets CNT to 0 |
| 7 | TIMER_CAP | 16 | count latched on the selected `ui[0]` edge; sets IRQ_CAP |
| 8 | PWM_PER | 10 + 3 | shared PWM period plus a ÷2^n prescaler (n = 0..7); 40 MHz / 2 / 526 = 38 kHz. Servos use the timer's PWM mode on uo[7] (16-bit resolution) |
| 9-11 | PWM_DUTY0-2 | 10 each | duty per channel. PWM0 can be ANDed with the timer compare output to make a gated IR carrier |
| 12 | UART_DATA | 8 | a write sends a byte (1-byte TX buffer); a read takes the received byte (1-byte RX buffer) |
| 13 | UART_CTRL | 16 | baud divisor (13 bits), flags: TX busy, RX full, RX overrun |
| 14 | SPI_DATA | 8 | SPI master byte transfer on uo[5:7]/ui[3]: LoRa, SPI expander, SD card, displays |
| 15 | SPI_CTRL | 4 | CS_n, clock divider, busy |
| 17 | IRQ_EN | 8 | timer compare, capture, UART RX, UART TX empty, GPIO edge, delta-sigma |
| 18 | IRQ_PEND | 8 | pending flags; write 1 to clear |
| 19 | GPIO_EDGE | 8 + 8 | per-`ui`-pin edge-interrupt enable and polarity |
| 20 | DSADC | 12 | delta-sigma result. External RC: `uo[5]` drives the feedback and `ui[2]` reads the comparator. A counter over a 2^N window gives about 8-10 bits at slow rates (optional) |

**Projected area:**

| Block | Area (µm²) |
|---|---|
| Timer (counter, prescaler, compare, capture, output) | 1,400 |
| 3 PWM channels with a shared period counter and prescaler | 1,100 |
| UART TX + RX | 1,300 |
| SPI master byte shifter (own pins on uo/ui) | 450 |
| GPIO (ALTFN, edge interrupts) | 500 |
| Interrupt controller + CSR logic (section 6) | 800 |
| Second chip select + memory reset sequence (section 4) | 350 |
| Bus decode / read mux | 600 |
| Exception trap entry (section 6) | 300 |
| **Subtotal** | **~6,800** |
| Optional: delta-sigma ADC | 400 |

The subtotal fits the ~8,000 budget with ~1,200 to spare: enough for the delta-sigma ADC (~400), not for the full motor pack (~1,400) without dropping something.

## 6. Interrupts

- **Recommended:** a minimal standard machine-mode interrupt. Standard toolchains and C
  handlers then just work.
  - CSRs: `mstatus` (MIE and MPIE only), `mie` (MEIE), `mip` (MEIP), `mtvec` (direct mode),
    `mepc`, `mcause`.
  - Only CSRRW, CSRRS and CSRRC (plus the immediate forms) on those CSRs, and MRET. Other CSR
    numbers read 0 and ignore writes.
  - `mepc`, `mtvec` and `mcause` live in the core region, the same trick as the pc and SERV's
    "CSRs as register-file entries". Only MIE and MPIE sit on the die.
  - One interrupt line: the OR of the enabled IRQ_PEND bits. Software reads IRQ_PEND for the
    source.
  - Worst-case latency is about two instructions (~75 µs at 20 MHz), which is fine for IR,
    UART at 9600 baud and buttons.
- **Exceptions: they trap to `mtvec`** (the user's decision, 2026-10-17).
  - These take the standard machine-mode trap, with `mcause` set:
    - ECALL (11) and EBREAK (3);
    - misaligned JAL, JALR and branch targets (0);
    - the 0x00000000 and 0xFFFFFFFF words (illegal instruction, 2).
  - On a trap, `mepc` gets the trapping pc, `mstatus.MPIE` gets MIE, MIE goes to 0, and execution
    jumps to `mtvec`.
  - Reserved encodings stay UNSPECIFIED. A core may trap them as illegal or execute them, but
    must stay live.
  - The contract's "fatal halt" rule goes away. The gates change accordingly: the ISS trap
    model, the trap programs (which test handlers and MRET), and riscv-formal's trap and pc
    checks. The cosim harness and the liveness fuzz then detect the end of a program from a
    handler convention, for example the handler writing a magic value to GPIO.
  - Projected extra cost on top of interrupts: about 200-400 µm² (the cause codes plus the
    trap-entry sequence).
- **Gates:** riscv-formal supports interrupts (rvfi_intr). The ISS gains a CSR and interrupt
  model, and cosim gains interrupt programs: a timer tick, UART RX, a GPIO edge.

## 7. Boot and upload

- **Reset:** the reset sequence (section 4), then a fetch from `0x0000_0000` in flash.
  - The program runs in place from flash, and crt0 copies `.data` to PSRAM and clears `.bss`.
  - There is no BOOT mode bit and no copy loop. Code may also run from PSRAM, for example a hot
    loop.
- **Upload:** the RP2350 writes the flash over USB with TT's flasher, which selects another
  project to free the `uio` pins. A host script wraps it, playing avrdude's role. No on-chip
  loader is needed.
- **EEPROM equivalent:** a reserved flash sector, written by the RP2350. The core only sends
  READ and WRITE, never write-enable or erase. In-system flash writes from the core are a later
  option.

## 8. The IR remote, end to end

- **Transmit (NEC):**
  1. PWM0 runs the 38 kHz carrier at 1/3 duty.
  2. The timer compare output gates it (AND) on `uo[1]`, which drives the IR LED through a
     transistor.
  3. Software loads the next mark or space duration into TIMER_CMP on each compare interrupt.
     The 562 µs units are about 15 instructions apart, plenty.
- **Receive:**
  1. A TSOP38238 demodulator output goes to `ui[0]`.
  2. The capture interrupt fires on both edges. Software computes widths from TIMER_CAP
     differences and decodes NEC (9 ms leader, 562 µs units).
- **Learning remote:** store the raw edge timings in RAM, then replay them through the TX path.

## 9. Gap to an Arduino Uno (ATmega328P at 16 MHz)

| Uno | This MCU (draft) | Gap |
|---|---|---|
| ~16 MIPS (AVR, about 1 instruction per clock) | ~0.05 MIPS at 40 MHz (H005: ~766 clocks per instruction at 16-bit addresses; 24-bit adds ~16 per transaction) | **About 600x slower.** Libraries that bit-bang microsecond timing (NeoPixel, software serial, `delayMicroseconds` precision) won't work. Everything timing-critical must be hardware |
| 32 KB flash, 2 KB SRAM, 1 KB EEPROM | 16 MB flash, 8 MB PSRAM, a flash sector as EEPROM (written by the RP2350) | **Better** |
| 20 GPIO, all bidirectional, with pull-ups | 8 in, 8 out, 0 bidirectional (the QSPI Pmod uses all `uio`) | No bidirectional pins; an SPI expander (MCP23S17) adds 16. No internal pull-ups |
| 6 PWM, 3 timers, input capture | 3 PWM, 1 timer with compare and capture | Fewer channels. More cost ~300 µm² each |
| 10-bit ADC, 6 channels, analog comparator | optional 1-channel delta-sigma with an external RC, slow | **No real analog.** TT analog needs analog tiles |
| UART, SPI, I2C hardware | UART and SPI hardware; no I2C (dropped) | No I2C: use UART/SPI parts |
| External and pin-change interrupts on every pin | edge interrupts on the 8 `ui` pins | Close |
| Hardware multiply (2 cycles) | none: RV32E without M, software multiply (hundreds of instructions) | Slow math. **[Decide]:** a serial Zmmul multiply instruction (~700-1,000 µm², reusing the serial ALU, ~32 extra cycles per multiply) |
| Watchdog, sleep, brown-out | timer-based watchdog (software), WFI sleep, no brown-out | Close (no brown-out) |
| USB upload and the Arduino IDE core | UART upload loader, GCC RV32E, no Arduino core yet | **Software work:** an Arduino core port (`pinMode`, `digitalWrite`, `analogWrite`, `millis`, `Serial`, `tone`, `attachInterrupt`, `SPI`, `Wire`) plus an upload tool |

**Closing the speed gap costs area or pins:**
- Quad SPI (the Pmod supports it): about 3-4x.
- A 40 MHz clock: 2x, and free if timing closes.
- Caching hot registers on the die: area.

Even all three together leave the MCU about 50-100x slower than a Uno. The honest pitch is an
*Arduino-like, very small, very slow* MCU: it's ideal for IR, buttons, LEDs, serial and sensors,
and wrong for bit-banged high-speed protocols.

## 10. Verification plan (the gates move with the contract)

- **ISS:** peripheral models (timer, PWM, UART, SPI shifter, GPIO edges, IRQ, CSRs, boot mode).
  The cosim harness gains pin-level models: a UART terminal, an IR LED and receiver loopback,
  and a flash chip.
- **New cosim programs:**
  - IR NEC loopback (TX into RX);
  - UART echo;
  - a timer interrupt tick;
  - PWM duty measured at the pins;
  - flash boot plus copy;
  - upload over UART into flash;
  - GPIO edge interrupts;
  - the liveness fuzz with peripherals enabled.
- **Formal:** register read/write checks per peripheral, interrupt entry and MRET, and the
  existing core checks with interrupts (rvfi_intr).
- **Gate level:** the TT test runs the IR loopback and UART echo on the netlist.

## 11. Phasing

1. Finish the core: V2 through the v2 formal gate, then H005 and later diets.
2. The user approves this spec, and the lead writes contract v3 plus the plan.
3. Gates first (ISS, harness models, programs, formal checks).
4. A peripheral seed: simple, correct, not optimized.
5. Area loop on the peripherals, one hypothesis track per block, measured against the 1x1
   budget.
6. Champion round: harden 1x1, tilefit, TT CI. Then the Arduino-style core and the upload tool
   (software).

## 12. Decisions

Decided by the user on 2026-10-17:
- **Memory board: TT's official QSPI Pmod**, option B: W25Q128 flash plus 2x 8 MB PSRAM on
  uio[0..7]. This supersedes the option C recommendation.
  - The contract and gates move to 24-bit addresses.
  - PSRAM's CS-low limit (about 8 µs, tCEM) must be met by every transaction.
  - Code boots from flash (XIP, or copied to PSRAM).
  - Single SPI first; quad mode later as a speed hypothesis.
  - All `uio` pins are used. GPIO is the 8 `ui` and 8 `uo` lines, plus an optional SPI I/O
    expander (MCP23S17) on uo/ui for bidirectional GPIO. The board's exact pinout and memory
    parts must be verified from its schematic first.
- **Radio:** off-chip, with no on-chip RF (TT digital tiles; analog muxes far too slow for
  RF). Either a BLE module over the UART or a LoRa module (SX1262/RFM95) over SPI on uo/ui.
- **Pins:** TT gives 24 user I/O on every shuttle (GF180 included), so expanders are the GPIO
  path.
- **Exceptions:** trap to `mtvec` (section 6).
- **Multiply:** none. Software multiply; no M or Zmmul.
- **Clock:** a 40 MHz target if timing closes, with a 25 ns signoff period. The PSRAM's 8 µs
  CS-low limit sets a floor of about 16-20 MHz.
- **Code runs from flash** (execute in place); data, the stack and the core region are in PSRAM A.
- **The core initializes the memory chips at reset** (section 4), so it boots on any board.
- **No I2C** in v3; UART and SPI parts instead.

### Motor-control candidates (projected areas, not measured; not yet chosen)

The CPU runs about 50-100k instructions/s, so anything with a sub-millisecond deadline must be in
hardware.

| Block | Area (µm²) | Why |
|---|---|---|
| Complementary PWM outputs + dead time (3 pairs) | ~500 | H-bridges / 3-phase BLDC without a shoot-through |
| Fault/brake input: hardware forces every PWM output off, latched | ~100 | stops the motor without the CPU in the loop |
| Cycle-by-cycle current limit: an external comparator ends the PWM pulse | ~80 | current control without an ADC |
| Quadrature encoder counter, 16-bit, synchronized inputs | ~700 | position/speed; software can't sample encoders fast enough |
| Hall sensors: GPIO edge IRQ + timer capture (exists) / hardware 6-step table | 0 / ~200 fixed, ~900 programmable | BLDC commutation; software is too slow above a few thousand RPM |
| Step/dir generator: timer compare as STEP + "stop after N steps" counter | ~600 | steppers (A4988/TMC2209 style drivers) |
| Watchdog | ~500 | safe stop if the firmware hangs |
| Center-aligned PWM mode | ~150 | lower ripple, synchronous current sampling |

The minimal "motor pack" (dead time, fault, current limit, encoder) is ~1,400. With the subtotal
above, that is over the ~8,000 budget unless it replaces optional or base blocks.

Still open (recommendation first):

1. **Delta-sigma ADC:** include it (+~0.4k), or leave it out.
2. **Motor control:** which of the candidates above, and what they replace.
